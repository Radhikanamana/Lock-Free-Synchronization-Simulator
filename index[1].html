⚛ Atomic Operations
An atomic operation is indivisible — it either completes entirely or not at all. No other thread can observe a partial state. This is the foundation of lock-free programming.
🔄 Compare-And-Swap (CAS)
CAS checks if a memory location holds an expected value, then only updates it if it matches. If another thread changed it first, CAS fails and the thread retries — no blocking needed.
🔒 Mutex
A mutex allows only one thread to enter a critical section at a time. Other threads block (wait) until the lock is released. Simpler but can cause contention.
⚡ Race Condition
When two threads read the same value and both write back, one update is silently lost. The final counter is lower than expected — this is called a lost update or data inconsistency.
💀 Deadlock
Deadlock occurs when two or more threads wait for each other to release locks, and none can proceed. Lock-free algorithms avoid deadlock entirely by never blocking threads.
